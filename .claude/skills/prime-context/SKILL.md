# Prime Context

Run this before any non-trivial implementation, debugging, or review work so edits start from an accurate picture of the repo.

> Single-page "coming soon" site: Vite + React 18 + TypeScript + Tailwind, entry at `src/main.tsx` rendering `src/App.tsx`. Static output in `dist/` is deployed to GitHub Pages (custom domain `vxjdev.com` via `public/CNAME` + Cloudflare DNS, DNS-only proxy mode). No `CLAUDE.md` exists yet — this skill is the closest thing to project instructions.

## Gather

- Read `README.md` (currently just the project title — don't expect more).
- Capture git context up front:
  - `git status --short --branch`
  - current branch or detached HEAD
  - `git log --oneline -5`
- Inspect local changes / recent diffs relevant to the task before editing.
- Read `src/index.css` and `tailwind.config.js` before any styling work — together they *are* the design system (custom `navy`/`slate`/`indigo`/`cream` palette, `display`/`body` font families, `fade-up`/`breathe`/`shimmer` keyframe animations).
- Map the current structure with `git ls-files` — the whole app is 3 files: `src/App.tsx` (page content/layout), `src/main.tsx` (React root), `src/index.css` (Tailwind base + custom styles). `public/` holds `CNAME` and `favicon.svg` and is copied as-is into `dist/`.
- `dist/` is a build artifact (untracked, gitignored) — never hand-edit it; it's regenerated by `npm run build`.
- For deployment, there is no dedicated deploy doc: the flow is `npm run deploy` (the `gh-pages` script in `package.json`, publishes `dist/` to the `gh-pages` branch). DNS is Cloudflare, pointed at GitHub Pages, DNS-only (not proxied) — see memory note on the custom domain if DNS/domain questions come up.

## Report

Before making edits or stating findings, report:

- repo state and branch status
- recent change context (what the dirty files and last commits are doing)
- files / docs reviewed
- task-relevant modules (almost always `src/App.tsx` and/or `src/index.css`/`tailwind.config.js` given the site's size)
- constraints identified — e.g. keep the existing color tokens/animation names in `tailwind.config.js` rather than inventing new ad hoc values; this is a static site with no backend/API/state management to reason about
- a verification plan with narrow checks first

## Verify

There is no test suite. Verification means:

- `npm run build` (`tsc && vite build`) to confirm TypeScript compiles and the production build is clean
- `npm run dev` and view in the browser to confirm behavior visually
- `npm run preview` to sanity-check the actual built output before deploying
- Before running `npm run deploy`, confirm with the user — it publishes to the live `gh-pages` branch / production domain

Run the narrowest applicable check first (`npm run build` or a focused dev-server view) before broad ones.
